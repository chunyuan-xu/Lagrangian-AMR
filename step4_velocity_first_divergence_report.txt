三、具体函数和物理量

首次造成串并行状态不同的函数：
  refresh_after_balance
    -> p4est_iterate
      -> quadrant_update_after_balance_callback

源码：
  src/main.cpp

首次不一致的物理量：
  悬点角点速度
  m_vara.VecCnData[idcnVelocity_cur][2]
  m_vara.VecCnData[idcnVelocity_lag][2]

该 callback 的物理操作是：
  middle_velo = 0.5 * (master_velo[0] + master_velo[1])

然后覆盖两个细单元的悬点：
  child.idcnVelocity_cur[hanging_corner] = middle_velo
  child.idcnVelocity_lag[hanging_corner] = middle_velo

同时还覆盖：
  idcnCoords_cur / idcnCoords_lag
并重新计算：
  volume
  density_cur
  pressure_cur

因此第4步首先看到速度和位置差异，随后会传播到密度、压力和AMR判据。

四、直接代码原因

quadrant_update_after_balance_callback 已实现 local/ghost 两套读取分支，例如：
  if (side[i]->is.hanging.is_ghost[0])
      child_data = &ghost_data[quadid];

但原 refresh_after_balance 的实际调用为：
  p4est_iterate(
      p4est,
      NULL,
      NULL,
      NULL,
      quadrant_update_after_balance_callback,
      ...);

即 callback 虽然能访问 ghost_data，iterate 却没有传 ghost 和 ghost_data。

结果：
  - 串行下 coarse-fine face 完全本地，callback 被执行，悬点速度被正确覆盖；
  - MPI 下该 coarse-fine face 跨 rank，NULL ghost 使该 face 不进入相同的 callback 覆盖路径；
  - 后续 p4est_ghost_exchange_data 只能同步已有 owner 数据，不能补做缺失的悬点约束计算。

五、因果验证

只做以下最小验证性修改：

  refresh_after_balance(p4est, ghost, ghost_data)

并将其 p4est_iterate 改为：
  p4est_iterate(
      p4est,
      ghost,
      ghost_data,
      NULL,
      quadrant_update_after_balance_callback,
      ...);

重新运行第4步串行/MPI 2核后：
  cells=1297/1297
  points=5188/5188
  NodeU max_abs=0
  NodeV max_abs=0
  NodeX max_abs=0
  NodeY max_abs=0
  Pressure max_abs=0
  density max_abs=0
  internal_energy max_abs=0

所有 Float32 输出逐位一致。该结果证明上述 ghost 缺失是直接原因，而非普通角点 MatrixP/RHS 求解误差。

六、错误传播链

第4步 AMR/balance 形成跨 rank coarse-fine face
  -> refresh_after_balance 未传 ghost/ghost_data
  -> MPI 未执行 quadrant_update_after_balance_callback 的悬点覆盖
  -> idcnVelocity_cur[2] / idcnVelocity_lag[2] 保留旧值
  -> write_solution 输出 NodeU/NodeV 差异
  -> 后续坐标更新产生 NodeX/NodeY 差异
  -> volume/density/pressure 逐步分歧
  -> 更晚时间步 AMR refine/coarsen 判据跨阈值
  -> 第100步网格拓扑数量不同
