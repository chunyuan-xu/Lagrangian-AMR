# 重构方法论与铁律（Refactoring Playbook）

从历史重构记录中提炼的可复用经验，供**制定新重构计划、推进里程碑、解决细粒度问题**时参考。调试/回归方法论见 [`SKILL.md`](SKILL.md)；门禁执行的完整 SOP 见 [`golden-gates.md`](golden-gates.md)；历史执行细节见 [`../history/`](../history/)。

## 1. 重构总顺序

```text
冻结基线 → 修复/确认 P0 正确性 → 明确状态与通信语义 → 抽取纯数值内核
→ 拆分 p4est adapter → 缩减主程序 → 再做性能优化
```

不能先机械拆文件、再处理通信和状态语义——那只是把隐式耦合从一个超大文件分散到多个文件，调试反而更难。

## 2. 两条黄金原则

- **原则一：每个子里程碑都必须通过串行三黄金回退**（Noh Uniform / Sod AMR / Sedov AMR）。短步冒烟、编译成功、单算例通过都不能替代。
- **原则二：先兼容迁移，里程碑闭环后再删除瘦身**。迁移阶段只做新增/包装/转发/调用点切换，不立即删旧实现；闭环（三黄金回退 + 必要 MPI/专项门禁通过）后再删。若旧符号与新接口无法共存必须提前删，在提交说明里记录原因/影响范围/恢复方法，并把删除限制在最小范围。

## 3. 架构铁律（性能与 MPI 安全）

- **最内层循环禁虚函数**：底层网格遍历（`p4est_iterate` 内、百万级面/角循环）禁用 vtable，用 CRTP / 函数对象 / Lambda 注入做静态多态。
- **MPI 交换结构体保持 POD**：挂到 p4est 树上参与通信的结构（如 `quad_data_t`）不加构造/析构/智能指针/vptr，否则二进制序列化崩溃；业务类只持其指针或引用。
- **禁止把 ghost mirror 当权威状态写入**：owner 拥有写入权，ghost 只读；通信缺失（漏传 ghost / 传 `NULL` ghost）是串并行分歧的最常见根因。
- **共享角点明确 owner 语义**：同一角点只有一个 owner 求解，保证跨 rank 确定一致。
- **单元对齐用稳定键** `(treeid, level, x, y)`，不依赖 `quadid`；网格数量或稳定几何集合不同就立即停字段比较，先定位拓扑首分歧。
- **include 循环用前置声明打破**（勿互相 include）；迁出头文件必须自带其依赖头，调用点同步路由。

## 4. 子里程碑统一执行模板（七步）

1. **范围冻结**：目标 / 非目标 / 涉及文件 / 预期不变的数值行为。
2. **前置基线**：改前三黄金回退，确认起点可信。
3. **兼容实现**：新增接口/模块，保留旧实现，不混入无关重命名和优化。
4. **调用迁移**：小批次切换调用点，每批至少编译 + 跑相关短测。
5. **主验收**：完整 Noh / Sod AMR / Sedov AMR 三黄金回退。
6. **清理瘦身**：只删已证无调用、被新实现覆盖的旧代码，再跑三黄金回退。
7. **独立提交**：记录变更范围、三算例结果、专项测试、删除清单、已知风险。

第 5 或第 6 步失败，子里程碑不得完成；优先恢复到上一个通过三黄金回退的提交再定位。

## 5. 细粒度闭环工作流（解决「细颗粒度问题」）

通信/状态语义重构不要「大功能做完再统一验收」，拆成可回退、可判定、可提交的小锚点：

1. **入口锚点**：确认当前提交、编译器、launcher/runtime、PATH、参数 checksum、输出目录；入口锚点必须实际通过完整 G0～G3，不能只信历史记录。
2. **单一假设、单一改动**：每个子锚点只动一个 callback / 一个字段组 / 一个访问权限 / 一个生命周期边界；不叠加未解释的实验改动。
3. **先读审计后写代码**：记录 callback 的 Requires / Reads / Writes / Invalidates / Exchange，区分 owner-local / remote snapshot / scratch。
4. **小步验证**：先 G0 + 专项测试，再完整串行 G1；G1 通过才算数值行为未回归。
5. **完整并行收口**：每个达到收口条件的粒度都跑完整四进程 G3（Sod + Sedov 两算例都实跑）；短 MPI smoke、单 rank、单算例都不能替代 G3。
6. **失败即停**：任一 G0～G3 失败，不进下一锚点、不提交完成态；定位「最近 PASS 锚点 → 当前 FAIL 改动」的最小区间，必要时二分回退。
7. **通过即提交追踪**：确认 staged diff 只含当前粒度的源码/文档，focused commit 并按授权推送。
8. **提交后确认**：记录 commit hash、工作树状态、下一锚点；证据缺失或混入未知修改就停在当前锚点。

核心不是增加测试数量，而是缩小「一个改动 ↔ 一个结论」的范围：任何失败都能归因到当前最小粒度，任何通过都能形成可恢复的 G0～G3 追踪点。

## 6. 每次提交的边界

- 一个提交只处理一个概念（如「封装 ghost 生命周期」）；不同时做算法修复和大规模重命名。
- 收口提交必须附 G0/G1/G3 结果（G2 记 retired / N/A）。
- 先保证串行三黄金，再跑该里程碑要求的 MPI/专项门禁。
- 每个 face/corner callback 显式说明：是否要 ghost、读哪些字段、写哪些字段、何时 exchange。

## 7. 门禁等级速查

| 门禁 | 内容 | 使用时机 |
|---|---|---|
| G0 | 干净编译、静态检查、相关单测 | 每批迁移后 + 每个收口点 |
| G1 | 完整串行 Noh/Sod/Sedov 黄金回退 | 子里程碑前后 + 清理后（强制）|
| G2 | retired / N/A | 不参与验收 |
| G3 | 完整 4 核 Sod + Sedov 并行黄金 + 守恒/负载 | 每个收口粒度（强制）|

完整 SOP、参考文件映射、失败分类见 [`golden-gates.md`](golden-gates.md)。

## 8. 会话上下文持久化（resume 保护）

每个子里程碑收口（G0～G3 通过并提交）后，同步更新 [`../history/context.md`](../history/context.md)（摘要，非日志），只记录能帮新会话续跑的信息：进度表 + 收口 hash、门禁记录索引、剩余任务、环境事实、下一步建议。未收口的中间态**不写入**。

## 9. 大版本收口后的诊断产物清理

每个大版本收口后，清理根目录**未跟踪**的诊断/调试产物（`*.log`、`*.plt`、summary json、`__pycache__/`、`.tmp/`、`build_*.o`、退役 `step_tests/` 等）。规则：只删未跟踪（先 `git ls-files --others --exclude-standard` 确认）；绝不删已跟踪文件；`reference/*.vtu`/`*.pvtu` 永不清除。

## 10. 重构完成定义（Definition of Done）

- `main.cpp` 不再承载具体数值算法；p4est/MPI 类型限制在 runtime/mesh adapter 层。
- 物理 / 几何 / AMR policy / transfer 可脱离 p4est 单测。
- ghost 生命周期、读写权限、exchange 边界由 API 表达；不再用裸 `void *` 在业务层传多种上下文。
- current / half / candidate 状态边界清晰；配置无隐藏默认继承，回归可重现。
- 每个迁移/清理完成点都有三黄金回退记录；4 核 Sod/Sedov 并行黄金（G3）与 `reference/par4_*` 一致。
- refine/coarsen 守恒、状态不变量、拓扑一致性有自动测试。
- 构建系统唯一可重复，源目录不被构建输出污染。
