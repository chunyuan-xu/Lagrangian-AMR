# M4.0 残留通信旧路径剥离与死计算短路计划

## 1. 基线和目标

M4.0 从 main 的 M3.5 收口合并提交开始。当前 main HEAD 为 `f482489`（M3.5 通信旧路径瘦身已闭合）。

M4.0 目标：把仍在活动回调中通过裸 `ghost_data[...]` 数组解引用的幽灵层读取，安全迁移为强类型 `GhostSession::remote()` 只读访问；对确认只读且结果被 owner 门禁丢弃的死计算做短路；最终全局抹除 `ghost_data` 占位符声明。

必须保持不变：

- 数值公式、callback 遍历/累加顺序和 AMR 判据；
- refine/coarsen/balance/partition 时序；
- ghost allocation、exchange、rebuild、generation 和 validity；
- owner-local 写入与 remote 只读访问语义；
- `quad_data_t`、ghost buffer 布局和 VTU/PVTU 输出；
- G1/G3 reference、文件名、字段和比较容差 `1e-12`。

本阶段明确延期：活动 `GhostSession::get()`、`session.data()` 可写路径、callback context 的进一步收紧、`corner_solver.h` 兼容声明、AMR 模块化（M4.1+）。

## 2. 固定门禁

每个代码里程碑都必须执行完整门禁：

- **G0**：同一 PowerShell 进程设置可写 `TEMP/TMP/TMPDIR` 后执行 Makefile clean build 和链接，并完成静态审计；
- **G1**：Noh Uniform → Sod AMR → Sedov AMR，首失败停止，比较容差 `1e-12`，`param.ini` 逐字节恢复；
- **G2**：`N/A — retired since 2026-08-04`；
- **G3**：四进程 Sod AMR → Sedov AMR，两个算例实际执行，首失败停止，比较 `reference/par4_*`，确认参数恢复。

reference 只读。`.vtu`、`.pvtu`、`.o`、`bin/`、`build/`、输出目录、summary JSON 和调试日志均为运行产物，不进入提交。

每次 G0/G1/G3 通过后在 main 创建 focused commit 并 push 到 GitHub；失败时停留在当前项，不向后推进。

## 3. 细粒度阶段

### A1：入口清单冻结（不改代码）

在 main `f482489` 冻结全部 `ghost_data` / `session.data()` / `.remote()` 引用清单，按三栏分类：

- **解引**：`ghost_data[id]` 实际读取（需迁移指针）；
- **仅声明**：`ghost_data = (quad_data_t*)user_data` 等占位符，未解引（收口阶段删除）；
- **注册传参方式**：每个相关 `p4est_iterate` 的 user_data 参数当前形态。

产出清单文档，作为每一项迁移的核对基线。

### B 系列：指针迁移（每项只做指针，独立 G0/G1/G3）

每个回调迁移必须**同时**处理：回调体内 `ghost_data[id]` → `context->session->remote(id)`，并把对应 `p4est_iterate` 注册的 user_data 从 `(void*)session.data()` 改为 `&GhostCallbackContext{&session}`。

顺序按「读量小、无联合体」优先：

| 项 | 回调 | 解引数 | 说明 |
|---|---|---|---|
| B1 | `quadrant_whether_allowing_coarsening_from_corner_callback` | 1 | 最小起步 |
| B2 | `quadrant_corner_velocity_callback` | 3 | corner 读取 |
| B3 | `quadrant_corner_minmod_estimate_callback` | 2 | corner 读取 |
| B4 | `quadrant_corner_to_point_matrix_assemble_callback` | 5 | corner 矩阵 |
| B5 | `quadrant_edge_minmod_estimate_callback` | 6 | edge 读取 |
| B6 | `quadrant_update_after_balance_callback` | 9 | 建议原清单遗漏项 |
| B7 | `quadrant_set_init_parent_edge_callback` | 7 | parent-edge |
| B8 | `quadrant_get_children_hanging_info_callback` | 2 | 建议原清单遗漏项；严格保持 M3.4 B14 的 exchange 时序 |
| B9 | `quadrant_hanging_point_matrix_assemble_callback` | 3 | hanging 联合体 |
| B10 | `quadrant_relaxed_hanging_solver_callback` | 12 | 已用 context；仅函数体内指针替换 |

### C 系列：死计算短路（可选、独立、每项一个回调）

仅在全部 B 系列闭合后考虑，且每项单独执行 G0/G1/G3：

- C1：`quadrant_edge_minmod_estimate_callback` 死计算短路；
- C2：corner 三个回调（velocity / minmod / matrix）死计算短路。

每项做守恒量、网格拓扑专项对比；任何 G3 漂移立即回退该单项。hanging 三个回调明确不短路（`is.full`/`is.hanging` 联合体拓扑高危）。

### D 系列：收口

- D1：全局抹除残留 `ghost_data = (quad_data_t*)user_data` 与 `= context->session->data()` 的未用声明（含 `whether_allowing_coarsening_from_edge_callback`、`set_gradient_zero_estimate_callback` 两个仅声明项）；
- D2：全量零残留审计 + 完整 G0/G1/G3（连续两次 G3）+ M4.0 focused commit + push。

## 4. 推进规则

静态审计 → 最小修改 → G0 → G1 → G3 → reference/参数/产物检查 → focused commit → push GitHub → 详细日志。任何门禁失败停留在当前项，不向后推进。
