# M3.5 通信旧路径瘦身计划

## 1. 基线和目标

M3.5 从 `main` 的 B15 收口提交 `bed5156` 开始。B15 已在当前机器实际通过 G0、G1 和 G3；M3.5 的目标是在不改变数值、AMR、ghost 生命周期和串并行黄金输出的前提下，删除已经完成迁移且全仓库零调用的通信旧路径。

本阶段必须保持不变：

- 数值公式、callback 遍历/累加顺序和 AMR 判据；
- refine/coarsen/balance/partition 时序；
- ghost allocation、exchange、rebuild、generation 和 validity；
- owner-local 写入与 `GhostSession::remote()` 只读访问语义；
- `quad_data_t`、ghost buffer 布局和 VTU/PVTU 输出；
- G1/G3 reference、文件名、字段和比较容差 `1e-12`。

本阶段明确延期：活动的 `GhostSession::get()`、`GhostSession::data()`、`remote()`、callback context、owner/remote 访问路径、`corner_solver.h` 兼容声明，以及 hanging repair、AMR transfer、Riemann、corner matrix、velocity、gradient 和任何活动 callback。

## 2. 固定门禁

每个代码里程碑都必须执行完整门禁：

- **G0**：同一 PowerShell 进程设置可写 `TEMP/TMP/TMPDIR` 后执行 Makefile clean build 和链接，并完成本阶段静态审计；
- **G1**：Noh Uniform → Sod AMR → Sedov AMR，首失败停止，比较容差 `1e-12`，`param.ini` 逐字节恢复；
- **G2**：`N/A — retired since 2026-08-04`，不恢复旧 step 检查；
- **G3**：四进程 Sod AMR → Sedov AMR，两个算例实际执行，首失败停止，比较 `reference/par4_*`，确认参数恢复。

reference 只读。`.vtu`、`.pvtu`、`.o`、`bin/`、`build/`、输出目录、summary JSON 和调试日志均为运行产物，不进入提交。

## 3. 细粒度阶段

### R0：入口基线复核

固定提交、环境、参数 checksum 和 reference checksum，重新执行 G0/G1/G3。R0 失败时不得进入代码清理。

### R1：清理契约和零调用证明

允许进入后续清理的五组对象：

1. `GhostSession::data_size_` 及仅维护它的赋值；
2. `quadrant_vtk_coord_update_callback`；
3. `Predict_refining_Quads` 与 `quadrant_predict_refining_quads_callback` 原子组；
4. `postprocess_after_coarsening` 与 `quadrant_update_after_coarsening_callback` 原子组；
5. `quadrant_update_parent_velo_press_callback`。

每组在删除前必须核对定义、声明、直接调用、`p4est_iterate` 注册、函数指针、宏和测试引用。R1 不删除源码；发现的新候选只能进入 deferred 清单。

### C1：删除 `GhostSession::data_size_`

只删除未被读取的私有字段及其初始化、赋值、复位；保持 `data_`、p4est allocation/free、exchange、generation、validity 和 rebuild/destroy 不变。

### C2：删除零调用 VTK 坐标 callback

只删除 `quadrant_vtk_coord_update_callback`。不得移动 writer、修改字段、文件名、输出顺序、时间元数据或坐标精度。

### C3：删除 prediction 死路径

原子删除 `Predict_refining_Quads` 与 `quadrant_predict_refining_quads_callback`。不得改变活动 refine criterion、tag、层级、周期、拓扑或 ghost rebuild。

### C4：删除 post-coarsening 死路径

原子删除 `postprocess_after_coarsening` 与 `quadrant_update_after_coarsening_callback`。不得迁移、修复或合并旧 callback，不得改变 coarsen/balance/partition、refresh 或 exchange/rebuild 时序。

### C5：删除 parent velocity/pressure 死 callback

只删除 `quadrant_update_parent_velo_press_callback`，不得改变活动 parent-edge、Riemann、corner、hanging、pressure、velocity 或 force assembly 路径。

### C6：全量审计

证明五组对象无定义、声明、调用或注册残留；同时证明活动 `GhostSession` API、owner-local 门禁、remote 读取、exchange/rebuild/generation/validity 和活动 callback 注册仍在。C6 不扩大删除范围。

### C7：最终收口

执行 clean G0、G1、G2 N/A，并连续两次完整 G3。确认每次 Sod/Sedov 实际执行、参数和 reference 不变，最后创建 M3.5 focused commit。

## 4. 推进规则

每个阶段遵循：静态审计 → 最小修改 → G0 → G1 → G3 → reference/参数/产物检查 → focused commit → 详细日志。任何门禁失败都停留在当前阶段，不向后推进。未经明确要求不 push M3.5 代码。
